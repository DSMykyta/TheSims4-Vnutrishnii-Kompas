211814 — ID конкретного бафа (наприклад "Заряджений кофеїном").

Як вони знаходять одне одного:

XML не лежить у читабельному вигляді — він спакований всередині .package. Гра при старті читає всі package в папці Mods, парсить тисячі XML, будує таблицю ID → обʼєкт. Коли потрібен баф 20193847562910384756 — знаходить за ID, не за іменем файлу.

Зібрати все в один package
Усе це можна писати в звичайному Notepad++, а Sims 4 Studio пакує і генерує ID.

Sims 4 архітектурно інша гра ніж Sims 3.

В Sims 3 був справжній open world — одна суцільна мапа з потоковим завантаженням, по якій сім міг йти/їхати без loading screens. Це було революційно, але страшенно жерло пам'ять і викликало довгі завантаження save-файлів коли вони розросталися.

EA розкритикували Sims 3 за продуктивність і для Sims 4 свідомо повернулися до lot-based архітектури. Тут світ — це не суцільна карта, а колекція ізольованих лотів + декоративний фон (background neighborhoods). Ось ключові обмеження:

1. Все поза лотом — це фейк-декорація. Будинки які ти бачиш в San Myshuno коли стоїш на своєму лоті — це не реальні моделі, це низькополігональні бекдропи без жодної interactivity. Туди не можна зайти, там нема navmesh, нема AI.

2. Симуляція тільки на твоєму лоті. Тільки сіми на твоєму активному лоті реально симулюються. Усі інші household у місті існують як abstract data в save-файлі — гра перевіряє кожні N хвилин чи треба їм виконати якісь дії (попастись на роботу, постаріти, народити дитину), але вони не ходять по фізичній мапі. Story progression це таблиця станів, а не реальне життя.

3. Pathfinding працює per-lot. Кожен лот має свою власну navmesh-мережу. Між лотами ніяких звʼязків. Глобальний navmesh не існує — і його неможливо додати модом, бо це частина C++ native engine коду, не Python.

4. Моди обмежені тим, що в Python. Sims 4 ділиться на дві частини: native C++ (рендер, фізика, завантаження world, navmesh) і Python (gameplay, AI, інтеракції, тюнінг). Моддери мають доступ тільки до Python. Native engine закритий повністю. Усе що стосується streaming geometry, world loading, відкритого простору — це native. Туди не достукатись.

5. Worlds в Sims 4 захардкожені. Кожен світ це бінарний .world файл з фіксованою сіткою лотів. Інструментів для повноцінного створення нових світів спільнота не має — TS4 World Builder існував і був примітивний, до того ж кожен патч ламав сумісність. Тому навіть нові custom-worlds типу Newcrest extensions просто переробляють існуючу структуру лотів.

6. Memory не витягне. Навіть якби чудом зробили open world через мод — гра почне крашитись на середньому залізі. Sims 4 і так має проблеми коли в save 100+ сімів. Ціле місто з активною симуляцією — RAM в небо.

Що моддери реально зробили в цьому напрямку:

Travel mods — швидші переходи між лотами без завантажувального екрану коли можливо (наприклад, миттєвий перехід для коротких подорожей в межах одного субсвіту).
Custom worlds — кілька авторів зробили нові світи (Roburky's, Pralinesims', Brookheights). Але це нові набори лотів з тими ж самими обмеженнями. Не open world.
More lots per world — спроби додати ще лотів існуючого свiту. Викликало критичні баги, не прижилось.
Live mode persistence — моди які роблять симуляцію NPC за межами активного лоту "розумнішою" (типу більше реалістичних розкладів дня). Це не open world, це краща абстрактна симуляція.
Що теоретично можна було б, але ніхто не робив:

Reverse-engineer native engine — декомпілювати C++ частину гри і написати свій world streaming. Юридично — порушення EULA. Технічно — ціла команда хакерів на роки роботи. Етично/legally — дуже сіра зона. Тому ніхто і не починав.
Hooks через DLL injection — як роблять для Skyrim (SKSE) чи Fallout (F4SE). Для Sims 4 існував Sims 4 Toolkit / Sims4Tools але це для unpacking package файлів, не для injection в живий процес. Engine-mod-loader типу SKSE для Sims 4 немає, бо EA не толерує таке і кожен патч переписує memory layout.
Висновок:

Open world у Sims 4 — це не задача моддерів, це задача нового двигуна. EA знає що фанати хочуть, але не зробить — їм вигідніше продавати DLC у поточній архітектурі. Sims 5 (Project Rene) обіцяв open world, але проект скасували в 2025.

Тобто моддери впираються в стіну яку поставили розробники свідомо. Усе що технічно можливо зробити поверх двигуна — або вже зроблено, або робиться. Те чого нема — фізично недосяжне через обмеження інструментів.

Чого досі нема і чому:

Ніхто не зробив повноцінний новий world з нуля з власним terrain, власною кількістю лотів у власних позиціях, власною формою карти. Причини:

1. EA свідомо не випустила Create-A-World. Для Sims 3 EA дала офіційний інструмент CAW — і саме через нього спільнота зробила сотні world. Для Sims 4 EA вирішила НЕ давати такий тулз. Вони знають що це вб'є продаж DLC-світів.

2. Бінарний формат .world файлів закритий. EA не задокументувала структуру цих файлів. Це проприєтарний формат з shadow lighting data, terrain heightmaps, lot positioning grid, navmesh, sky data, weather zones. Reverse-engineering зайняв у спільноти роки.

3. Один моддер працює на цьому самотужки.

TwistedMexi (автор T.O.O.L. mod, Better Build/Buy) з 2019 року робить власний Create-A-World mod під кодовою назвою Project Raven. Це найскладніший мод у всій історії спільноти Sims 4. Він прямо каже: "це найскладніший мод в історії TS4 моддингу".

Що CAW зможе коли вийде:

Customizable terrain
Lot placement (свої лоти у своїх позиціях)
Об'єкти декорацій
Lighting customization
Apartment support (планується)
Чого CAW не зможе (за словами автора):

Open world (engine-level обмеження, undoable)
Повністю reshape карту (треба обирати з існуючих world templates і модифікувати)
Поточний статус CAW: alpha, тільки для тестерів через Patreon. Розробка триває з 2019 — це 6 років. Окремі апдейти типу lighting tools займали по 2 місяці. Public release досі немає, дати нема.

4. Чому ОДИН моддер а не команда.

Сполоктура реверс-енджинирінгу в спільноті дуже вузька. Декомпілювати Python-частину гри легко (uncompyle6). Але world-системи в Sims 4 — це native C++ код, доступу до якого нема. TwistedMexi працює через memory injection і Python hooks які зачіпають native виклики через спеціальні obfuscated інтерфейси. Кількість людей у світі які мають таку експертизу і одночасно цікавляться Sims 4 — одиниці. Інших великих world-моддерів просто немає.

5. Кожен EA-патч може зламати все.

Sims 4 патчиться щомісяця. CAW тримається на дуже тонкому memory hooking — будь-яке оновлення гри може миттєво зламати весь мод. Тому TwistedMexi мусить підтримувати свій код у близько-актуальному стані постійно. Це додатковий фактор чому ніхто інший не починає схожі проекти — підтримка stricter ніж розробка.

Що це за програма
Standalone Windows-програма (без встановлення, просто .exe який запускаєш) для оновлення Sims 4, керування DLC і обслуговування гри. Написана на Python 3.12+. Безкоштовна, opensource.

Що вона вміє
Оновлення гри одним кліком Автоматично визначає твою поточну версію гри (хешує системні файли і порівнює з базою 135+ відомих версій), потім підраховує найкоротший шлях патчів від твоєї версії до останньої і завантажує тільки потрібні дельти. Підтримує продовження завантаження якщо обірвалося.

Керування DLC Перемикає 109 DLC. Сама визначає який тип "крека" в тебе встановлено (5 форматів: RldOrigin, Codex, Rune, Anadius Simple, Anadius Codex-like). Є режим автоматичного перемикання — програма сканує папки гри і вмикає DLC залежно від наявності їх файлів. Назви DLC локалізовані 18 мовами.

Завантаження DLC через CDN Завантажує будь-який DLC напряму з власного сервера (Cloudflare Worker що проксує seedbox). Паралельні фонові завантаження з продовженням і перевіркою цілісності через MD5.

Контроль доступу до CDN Кожен клієнт авторизується через JWT токен. Власники CDN можуть банити користувачів за IP/Machine ID/UID, перемикати CDN між публічним і приватним режимом, моніторити підключених клієнтів, масово керувати запитами доступу.

Інтеграція з GreenLuma 2025 GreenLuma — це окрема програма для відкриття DLC через Steam. Цей updater вміє її повністю керувати: встановлювати, видаляти, парсити .lua файли, інжектити ключі в config.vdf, копіювати .manifest файли. Користувачі які купили DLC через Steam можуть надати свої ключі дешифровки спільноті — і ці ключі автоматично роздаються через CDN іншим користувачам.

DLC Packer Пакує встановлені папки DLC у ZIP-архіви які можна роздавати. Та ж функція в зворотному напрямку — імпортує чужі DLC-архіви.

EA DLC Unlocker Один клік — встановлює або видаляє EA DLC Unlocker з автоматичним підняттям прав адміна.

Event Rewards Unlocker (розблокування нагород за івенти) Розблоковує нагороди живих івентів Sims 4 через патч файлу accountDataDB.package. Зчитує твої EA акаунти з UserSetting.ini і патчить шаблон з усіма відомими нагородами. Підтримує до 10 акаунтів.

Два режими: Live events (онлайн — нагороди закріплюються за акаунтом назавжди), Ended events (офлайн — перезапишуться при наступному заході в онлайн).

Зараз підтримує 8 івентів: Lost Legacies (Лют 2026), Deck the Palms (Гру 2025), Forever Friends (Вер 2025), Nature's Calling (Чер 2025), Blast From The Past (Лют 2025), Cozy Celebrations (Гру 2024), Reaper's Rewards (Вер 2024), Happy at Home (Чер 2024).

Доступний як вкладка в програмі, як CLI-команда, або як веб-інструмент який працює прямо в браузері (нічого не завантажується на сервер).

Зміна мови гри Перемикає між 18 мовами гри. Оновлює одночасно реєстр Windows, файли RldOrigin.ini і конфіг анадіус-крека. За потреби може довантажити мовні файли з depot Steam.

Mod Manager Керування модами прямо з GUI.

Діагностика Автоматичні перевірки системи: VC Redistributable, .NET Framework, чи Windows Defender блокує папку гри, права доступу до папки, проблеми зі шляхами (крапки з комою, не-ASCII символи), чи антивірус не запхав файли в карантин. Валідатор файлів сканує папки DLC на пошкоджені або відсутні файли.

Резервне копіювання (бета) Перед патчем робить резервну копію файлів які будуть змінені. Можна налаштувати скільки бекапів зберігати, відновити будь-яку попередню версію.

Тому для Steam існує GreenLuma 2025 — окремий інструмент який обманює Steam і змушує його думати що ти володієш всіма DLC. Sims4Updater має повну інтеграцію з GreenLuma.

Якщо у тебе чиста піратка:

Жодних конфліктів. EA App і Steam не задіяні взагалі.

Ризики незалежно від варіанту:

Так, EA App завантажується автоматично навіть для Steam-версії — це нормально, не баг. Sims 4 на Steam все одно використовує EA App як другий launcher для DRM. Ти не уникнеш його, навіть якщо хочеш — гра без EA App не запуститься.

Тобто на Steam у тебе дві DRM-перевірки одночасно:

Steam перевіряє чи ти володієш базовою грою + DLC
EA App перевіряє той самий ownership зі свого боку
Крек має обійти обидві.

Що таке GreenLuma
GreenLuma 2025 — це окрема програма яка обманює Steam-частину DRM. Вона маніпулює локальним Steam клієнтом щоб він думав що ти володієш DLC якими насправді не володієш.

Технічно вона робить три речі:

Додає ID кожного DLC до AppList Steam — список програм які ти "купив". Steam потім рапортує гру що ти володієш цими DLC.
Ставить ключі дешифровки в config.vdf Steam — без цих ключів навіть якщо файли DLC є на диску, гра не зможе їх прочитати.
Кладе manifest-файли в depotcache — це інструкції які кажуть Steam де лежать конкретні файли DLC.
Запускаєш Steam через DLLInjector.exe (приходить разом з GreenLuma) замість звичайного steam.exe, і Steam стартує з підмінами в пам'яті.

Важливо: GreenLuma обманює тільки локальний Steam. На серверах Steam ти DLC не володієш. Якщо Steam колись перевірить серверну сторону — буде видно що ти граєш з DLC яких у тебе немає на акаунті. Зазвичай Steam цього не робить для Sims 4, але прецеденти бувають.

Як це склеюється з Sims4Updater для Steam
Sims4Updater має повну інтеграцію з GreenLuma 2025 — окрема вкладка в інтерфейсі. Послідовність:

Завантажуєш Sims4Updater + GreenLuma 2025 окремо (посилання в README).
У Sims4Updater вказуєш папку GreenLuma і .lua файл (це файл з усіма ключами і manifest ID для DLC Sims 4 — лежить десь у спільноті).
Sims4Updater автоматично:
Парсить .lua
Заповнює AppList потрібними DLC App ID
Інжектить ключі в config.vdf
Копіює .manifest файли в depotcache
Запускаєш Steam через DLLInjector.exe.
Запускаєш Sims 4 через Steam → Steam віддає всі DLC як "куплені".
Гра стартує через EA App → EA App теж бачить ownership через те ж саме оточення.
Тобто GreenLuma вирішує Steam-частину, а крек який ставить Sims4Updater (наприклад через EA DLC Unlocker або через cracked exe) вирішує EA-частину.

Реальний сетап для тебе
Раз у тебе Steam-версія, ти не зможеш просто запускати cracked exe як той хто має Origin/EA App без Steam — Steam відстежує цілісність файлів і буде їх відновлювати при кожному запуску.

Тому для тебе шлях такий:

Sims4Updater — оновлює базову гру, керує конфігом
GreenLuma 2025 — обманює Steam про володіння DLC
EA DLC Unlocker — обманює EA App про володіння DLC
Усі троє автоматизуються через інтерфейс Sims4Updater. Один раз налаштовуєш, далі запускаєш гру через DLLInjector → Steam → EA App → гра з усіма DLC.

Альтернатива якщо це здається складно: просто грати в чисту піратку поруч зі Steam-версією. Твоя Steam-версія залишиться як є, а в окремій папці поставиш повністю крек-версію. Без GreenLuma, без EA App-обходу, просто запускаєш Game-cracked\Bin\TS4_x64.exe і граєш.

Декілька технічних наслідків які варто проговорити:

1. Lot 51 Core Library як dependency справді відпадає. Це означає що для injection-style операцій (додавання інтеракцій до існуючих об'єктів типу phone/computer) ти будеш писати свій injection шар з нуля. Це робиться через стандартні tuning механізми:

_super_affordances injection через <L n="_super_affordances"> додавання у клон обʼєкта (не override)
Або власний мінімальний .ts4script з простим pattern: services.affordance_manager().get(target_id).add_super_affordance(your_affordance)
Перевір на extracted XML як EA сама декларує super_affordances в object_phone_basic.xml або object_computer_basic.xml. Якщо вистачає tuning-only injection через додаткові tuning files які додають у списки — добре. Якщо EA вимагає overriding базового tuning (а не addition) — тоді або (а) приймаєте override з compatibility caveat, (б) робите свій script.

2. Custom rabbit-hole без XML Injector. XML Injector — це Scumbumbo's утиліта яка спрощує injection patterns. Без нього ти або робиш override базового tuning, або пишеш свій крихітний script. Реалістично для MVP — повний override непотрібен, можна обійтися:

Self interactions (на сімі) — додаєш через trait's own _super_affordances список. Це чистий tuning, нічого не override-ить.
Phone/computer interactions — складніше. Або власний мінімальний script (~30-50 рядків Python), або відкласти phone/computer integration на post-MVP.
Я б ставив на MVP self-interactions only, phone integration винести в Milestone 3-4. Це ще скорочує scope MVP без втрати корисності.

3. Risk: tuning hash collisions і load order. Без Lot 51 Core та інших libraries — ти єдиний хто пише tuning у своїй ніші. Менше ризику конфліктів, але також немає захисту від твоїх же помилок (типу випадкове перевикористання FNV64 hash). ids_registry.csv стає критично важливим, не просто корисним.

Що далі
Codex, у тебе на твоєму боці зараз нема активних задач крім ще одної pre-extraction перевірки яку я б запропонував:

Сформулювати PowerShell snippet для генерації SHA-256 manifest який Микита запустить після Extract All. Це 5 рядків, але фіксує форматування manifest CSV щоб не довелося потім переробляти. Зразок:
powershell
Get-ChildItem -Path .\research\extracted -Recurse -File | 
  ForEach-Object {
    $hash = (Get-FileHash $_.FullName -Algorithm SHA256).Hash
    "$($_.FullName.Replace((Resolve-Path .\research\extracted).Path + '\', ''))" + 
    ",$hash,$($_.Length),$(Get-Date -Format 'yyyy-MM-dd'),1.123.85.1020"
  } | Out-File -FilePath .\research\snapshot_manifest.csv -Append -Encoding utf8
Адаптуй під свій точний формат manifest колонок. Це автоматизує step "згенерувати hashes" з мого попереднього повідомлення.
