Sims 4 ділиться на дві частини: native C++ (рендер, фізика, завантаження world, navmesh) і Python (gameplay, AI, інтеракції, тюнінг). Моддери мають доступ тільки до Python. Native engine закритий повністю. Усе що стосується streaming geometry, world loading, відкритого простору — це native. Туди не достукатись.
5. Worlds в Sims 4 захардкожені.
Кожен світ це бінарний .world файл з фіксованою сіткою лотів. Інструментів для повноцінного створення нових світів спільнота не має — TS4 World Builder існував і був примітивний, до того ж кожен патч ламав сумісність. Тому навіть нові custom-worlds типу Newcrest extensions просто переробляють існуючу структуру лотів.
6. Memory не витягне.
Навіть якби чудом зробили open world через мод — гра почне крашитись на середньому залізі. Sims 4 і так має проблеми коли в save 100+ сімів. Ціле місто з активною симуляцією — RAM в небо.
Що моддери реально зробили в цьому напрямку:

Travel mods — швидші переходи між лотами без завантажувального екрану коли можливо (наприклад, миттєвий перехід для коротких подорожей в межах одного субсвіту).
Custom worlds — кілька авторів зробили нові світи (Roburky's, Pralinesims', Brookheights). Але це нові набори лотів з тими ж самими обмеженнями. Не open world.
More lots per world — спроби додати ще лотів існуючого свiту. Викликало критичні баги, не прижилось.
Live mode persistence — моди які роблять симуляцію NPC за межами активного лоту "розумнішою" (типу більше реалістичних розкладів дня). Це не open world, це краща абстрактна симуляція.

Що теоретично можна було б, але ніхто не робив:

Reverse-engineer native engine — декомпілювати C++ частину гри і написати свій world streaming. Юридично — порушення EULA. Технічно — ціла команда хакерів на роки роботи. Етично/legally — дуже сіра зона. Тому ніхто і не починав.
Hooks через DLL injection — як роблять для Skyrim (SKSE) чи Fallout (F4SE). Для Sims 4 існував Sims 4 Toolkit / Sims4Tools але це для unpacking package файлів, не для injection в живий процес. Engine-mod-loader типу SKSE для Sims 4 немає, бо EA не толерує таке і кожен патч переписує memory layout.

Висновок:
Open world у Sims 4 — це не задача моддерів, це задача нового двигуна. EA знає що фанати хочуть, але не зробить — їм вигідніше продавати DLC у поточній архітектурі. Sims 5 (Project Rene) обіцяв open world, але проект скасували в 2025.
Тобто моддери впираються в стіну яку поставили розробники свідомо. Усе що технічно можливо зробити поверх двигуна — або вже зроблено, або робиться. Чого досі нема і чому:
Ніхто не зробив повноцінний новий world з нуля з власним terrain, власною кількістю лотів у власних позиціях, власною формою карти. Причини:
1. EA свідомо не випустила Create-A-World.
Для Sims 3 EA дала офіційний інструмент CAW — і саме через нього спільнота зробила сотні world. Для Sims 4 EA вирішила НЕ давати такий тулз. Вони знають що це вб'є продаж DLC-світів.
2. Бінарний формат .world файлів закритий.
EA не задокументувала структуру цих файлів. Це проприєтарний формат з shadow lighting data, terrain heightmaps, lot positioning grid, navmesh, sky data, weather zones. Reverse-engineering зайняв у спільноти роки.
3. Один моддер працює на цьому самотужки.
TwistedMexi (автор T.O.O.L. mod, Better Build/Buy) з 2019 року робить власний Create-A-World mod під кодовою назвою Project Raven. Це найскладніший мод у всій історії спільноти Sims 4. Він прямо каже: "це найскладніший мод в історії TS4 моддингу".
Що CAW зможе коли вийде:

Customizable terrain
Lot placement (свої лоти у своїх позиціях)
Об'єкти декорацій
Lighting customization
Apartment support (планується)

Чого CAW не зможе (за словами автора):

Open world (engine-level обмеження, undoable)
Повністю reshape карту (треба обирати з існуючих world templates і модифікувати)

Поточний статус CAW: alpha, тільки для тестерів через Patreon. Розробка триває з 2019 — це 6 років. Окремі апдейти типу lighting tools займали по 2 місяці. Public release досі немає, дати нема.
4. Чому ОДИН моддер а не команда.
Сполоктура реверс-енджинирінгу в спільноті дуже вузька. Декомпілювати Python-частину гри легко (uncompyle6). Але world-системи в Sims 4 — це native C++ код, доступу до якого нема. TwistedMexi працює через memory injection і Python hooks які зачіпають native виклики через спеціальні obfuscated інтерфейси. Кількість людей у світі які мають таку експертизу і одночасно цікавляться Sims 4 — одиниці. Інших великих world-моддерів просто немає.
5. Кожен EA-патч може зламати все.
Sims 4 патчиться щомісяця. CAW тримається на дуже тонкому memory hooking — будь-яке оновлення гри може миттєво зламати весь мод. Тому TwistedMexi мусить підтримувати свій код у близько-актуальному стані постійно. Це додатковий фактор чому ніхто інший не починає схожі проекти — підтримка stricter ніж розробка.

Native шар (C++): rendering, lighting, navmesh, animation playback engine, world streaming, AI core, life stages, species, weather effects, occult transformations, camera, UI framework. Закритий, моди не дотягуються.
